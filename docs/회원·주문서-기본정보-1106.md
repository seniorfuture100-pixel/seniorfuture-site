# 첫 신청 기본 정보 저장 — v1.0.241

## 구현

- 회원 주문서에서 아임웹 기본 회원 수정 폼(`/dialog/join.cm`)을 읽어 저장된 정보를 확인한다. 기존 주문서의 자동 입력값을 회원 저장값으로 간주하지 않는다.
- 회원 이름·연락처·안내 이메일 중 빠진 값이 있으면 기본 정보 보완 링크를 표시하고 신청·결제 진행을 막는다.
- 기본 정보 보완 화면은 누락된 입력 그룹만 보여 준다. 아임웹의 실제 회원 수정 폼과 저장 기능을 그대로 사용한다. 모든 원래 숨김 필드·보안 토큰·기존 마케팅 동의 값은 보존한다.
- 이름·연락처는 회원 기본 필드에 저장한다. 안내 이메일은 기존 사용자 정의 `이메일` 항목을 재사용하고 화면에서 `신청 안내 이메일`로 구분한다. 해당 값이 비어 있으면 계정 이메일을 기본 안내 주소로 사용한다.
- 로그인 계정 `uid`와 비밀번호는 수정하지 않는다. 아임웹이 본인 확인을 요구하면 기존 현재 비밀번호 입력 절차를 유지한다.
- 저장은 아임웹 `SITE_MEMBER.joinSubmit`이 처리하고 성공 후 원래 주문서로 복귀한다. 복귀한 주문서는 회원 저장값을 다시 읽는다. 신청·결제를 자동 제출하지 않는다.
- 저장된 회원 정보가 있으면 다음 주문서의 이름·연락처·이메일을 채운다. 이번 주문만 수정하는 입력과 `회원정보도 수정` 링크를 구분한다. 기존 완료 주문은 변경하지 않는다.
- 연락처·이메일 값은 localStorage/sessionStorage나 별도 서버에 저장하지 않는다.
- 조회 실패·세션 만료·저장 거절을 성공으로 표시하지 않는다. 복귀 주소는 같은 사이트의 `/shop_payment` 경로로 제한한다.

## 검증

- 로컬 전용 모의 서버에서 운영 소스의 실제 공통 helper·주문서 코드·프로필 저장 UI 함수를 사용했다. 백엔드는 합성 회원 데이터로 대체했다.
- 누락 정보가 있으면 기존 주문서가 채워져 있어도 진행 차단.
- 중첩된 실제 아임웹 폼 구조와 대조. 연락처만 누락되면 연락처만 표시. 오류 후에도 누락 항목만 표시.
- 기본 정보 저장 → 주문서 복귀 → 저장값 자동 입력 → 새 주문서에서 재사용 확인.
- 안내 이메일 변경 후 주문서 반영, 로그인 이메일·마케팅 동의·보존용 숨김 값 유지 확인.
- 조회 실패·저장 거절 시 차단 및 재시도 확인. 비회원 주문서의 기존 동작 보존.
- 로컬 화면 390px·1280px에서 가로 넘침 없음.
- 복귀 주소와 누락 판정 단위 검사 13개 통과. 빌드·ES5/비밀값/중복 검사 및 기본 화면 smoke 검사를 별도로 실행한다.
- JS brotli 약 146KB: 기능 추가에 따라 기존 145KB 한도를 147KB로 조정. 외부 SDK는 추가하지 않았다.

## 운영 검증 경계

- 이 문서 작성 시 운영 사이트는 v1.0.240이다. v1.0.241 푸시·태그·Header Code 교체는 아직 하지 않았다.
- 실제 아임웹 화면에서 회원 폼 구조와 기존 필드·읽기 전용 로그인 이메일을 확인했다. 실제 회원정보를 바꾸거나 신청·결제를 완료하지 않았다.
- 네이버·구글 각각의 일반회원 로그인 후 저장까지 완료하는 운영 E2E, 실제 아임웹 저장 성공 후 다음 신청 확인은 배포 전후 별도 검증이 필요하다. 모의 시험을 해당 검증의 완료로 보지 않는다.
- 구현은 기존 일반회원 `이메일` 사용자 정의 항목을 사용한다. 관리자가 해당 항목명을 바꾸면 `fields()`의 허용 이름도 함께 검토한다. 개인정보 수집 항목·동의 단계·회원가입 필수 설정을 이번 코드에서 변경하지 않았다.
- 이전 미커밋 수정 4개는 보존했으며, 해당 변경은 별도 빌드 작업본에 포함하지 않았다.
