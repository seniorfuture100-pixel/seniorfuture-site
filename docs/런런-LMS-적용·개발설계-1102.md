## 1. 이번에 새로 확인한 사실

### 1-1. 우리 사이트·관리자 [실측]

**회원**
- 전체 3명이에요: 관리자 1명, 시험 계정 2명(김토스, 정동호).
- 실제 유료 구매 고객은 아직 없어요. → **옮길 기존 수강생·진도가 사실상 없어요.**
- 예전 기수(8~11기) 수강생은 아임웹 회원이 아니에요.

**회원 그룹 3개** (관리자가 시험 구매로 들어가 있어요)
- 수강 · 장기요양기관 운영 실무 1기
- 무료 라이브 그룹 10.30
- VOD 수강 · 시니어트렌드 2027

**상품**

|---|---|---|
| 83 VOD | 초고령사회 대전환 지도 | 아임웹 **'회원그룹 이용권'** 상품이에요. 사면 'VOD 수강 · 시니어트렌드 2027' 그룹이 **30일** 주어져요. **지금 판매 상태는 '판매안함'**(교육 목록에서 빠져 있어요) |

**강의실 주소**
- 손님이 '나의 강의실'로 가면 로그인 뒤 **주문 목록**(`/shop_mypage/?m2=order`)으로 돌아가요.
- 사이트에 `/learn-run` 페이지는 아직 없어요(301 → 홈).

### 1-2. 아임웹 공식

**회원그룹 이용권**
- 사면 정해진 기간 동안 그룹이 바뀌고, 만료일 23:59에 끝나요. [공식 FAQ 71371, 검색 인용]
- **취소·환불해도 그룹은 자동으로 빠지지 않아요.** 관리자가 직접 빼야 해요. [공식 FAQ 72202/72211, 검색 인용 — 시험 주문으로 재확인 필요]
- 그룹을 한꺼번에 바꾸면 이용권 기간이 사라져요. API로 그룹을 넣을 때는 만료일 필드가 없어요. [공식 개발 문서]

**이용권·디지털 상품의 주문 처리**
- 결제 완료와 동시에 '구매확정(거래 종료)'이 돼요.
- 구매자는 취소를 신청할 수 없어요. 관리자만 할 수 있어요(거래 재개 → 취소 → 환불).
- 입금 대기는 무통장·가상계좌에서만 생겨요. [공식, 검색 인용]

**Open API·웹훅** [공식 개발 문서]
- 결제·취소·환불 웹훅이 있어요: `ORDER_DEPOSIT_COMPLETE`, `ORDER_CANCEL_COMPLETE`, `ORDER_REFUND`
- 회원 그룹 API가 있어요: `PUT /member-info/members/{uid}/groups`
- **그룹 변경 웹훅과 구매확정 웹훅은 없어요.**
- OAuth 토큰은 Access 2시간, Refresh 90일이에요.
- 주문 API는 주문관리 v2에서만 돼요.
- 웹훅은 이벤트마다 받는 주소 1개예요. 시험 연동 사이트에는 오지 않아요.

**메뉴 접근 권한** [공식]
- 고를 수 있는 것: 모든 사용자 / 로그인 사용자 / 소유자 / 사용자 지정 그룹
- 함께 쓸 수 있는 옵션: '로그인창 자동 표시', '권한이 없을 때 메뉴 숨김'

**정기구독** [공식]
- Starter 요금제 이상, 카드만, 토스페이먼츠·나이스페이, PG 심사 2~3주
- 구독 중 그룹을 자동으로 주는 기능은 문서에 없어요.

### 1-3. 런런 공개 코드·헤더 [관측]

**구조**
- 강의실은 `learn-run.me/student/...`를 우리 페이지 안에 **iframe으로 띄우는** 방식이에요.
- 회원은 `memberCode`·`siteCode`로 알아봐요.

**⚠ 도메인 위험**
- 응답 헤더 `frame-ancestors`가 `*.imweb.me`, `*.imweb.co.kr`만 허용해요.
- **우리 대표 도메인 `seniorfuture.kr`에서 강의실이 뜨는지 보장이 없어요.**
- 관리자 화면에 '강의실 허용 도메인 설정(extraDomains)'이 있어서, 이걸로 풀리는 것으로 보여요.
- → **설치하면 가장 먼저 시험할 항목**이에요.

**딥링크 경로가 있어요**
- 경로: `/student/my-learning`, `/student/courses/:id`, `/student/learn/:courseId/lesson/:lessonId`
- 우리 페이지 주소로 바로 열리는지는 [미확인]이에요.

**기수(cohort)**
- 강좌 아래 기수가 있고, 기수마다 시작일·종료일이 있어요.
- **아임웹 상품 옵션 값을 기수에 연결**하면 결제 시 자동 등록돼요.
- 화면 안내에 **"환불하면 자동으로 제외됩니다"**라고 적혀 있어요.
- 기수에 수강생을 직접 추가할 수도 있어요.

**그 밖에**
- '아임웹 회원·그룹 동기화' 버튼이 있어요. 그룹 변경은 실시간이 아니라 동기화 방식일 수 있어요. [해석]
- 모바일(1024px 미만)에서는 수강 중인 강좌를 바로 이어보기로 넘겨요.
- 내보내기는 자료 다운로드 현황과 결제 내역 CSV만 보여요. **진도 일괄 내보내기와 대량 등록은 찾지 못했어요.**
- **런런 구독이 끊기면 수강생 시청이 바로 멈춰요.** 화면 문구: "사이트의 구독이 만료되어 강의 시청이 잠시 중단되었어요"
- 런런 구독 자체의 환불은 7일 이내이면서 사용 이력이 없을 때만 돼요. **영상을 1번이라도 재생하면 환불이 안 돼요.** → 체험 기간 안에 판단해야 해요.
- 회원 이름·이메일·전화번호·그룹을 동기화해서 보관하는 것으로 보여요. 개인정보처리방침에 위탁 항목을 추가해야 할 수 있어요.

**Enterprise 할인가**
- 코드에도 449,000원으로 들어 있어요. 50% 할인이면 499,000원이라 계산이 맞지 않아요.

## 3. 개발 설계 (시니어퓨처 공통 코드)

원칙
- 수강 권한은 **런런 서버와 아임웹**이 정해요. 우리 코드는 길 안내만 해요.
- 버튼이 보이는 것과 캐시는 권한의 근거로 쓰지 않아요.

### 3-1. 설정 한 곳 (`site/blocks/config.js`)

```js
// 런런 연결 — on:false 면 지금 강의실 그대로(되돌리기 스위치)
SF_SITE.lms = {
  on: false,
  path: '/learn-run',                  // 아임웹 메뉴 URL(런런 공식 설치 방식)
  items: {                             // 상품 번호 → 강의실 안내 방식
    83:  { label: '온라인 강의' },
    82:  { label: '다시보기·자료', keepRoom: true },   // 일정·톡방은 지금 강의실 유지
    103: { label: '멤버 세미나 다시보기' }
  }
};
```

- 상품 단위로 하나씩 켤 수 있어요. 문제가 생기면 `on:false` 한 줄로 원래대로 돌아가요.

### 3-3. 아임웹·런런 설정 (사람이 하는 일)
1. **앱 설치(사장님)**
   - 아임웹 앱스토어 '사이트에 추가' → 권한 동의
   - 앱 관리에서 '연동 완료' 확인
2. **런런 관리자**
   - 강의실 허용 도메인: `seniorfuture.kr`, `www.seniorfuture.kr`
   - '영상 재생 허용 다시 맞추기' 실행
3. **디자인 모드**
   - 메뉴 페이지 URL `learn-run`
   - 접근 권한: '로그인 사용자' + '로그인창 자동 표시'
   - 메뉴에서는 숨기고 게시
4. **강좌·기수·연결**: 2절 표대로

### 3-4. 나중에 필요하면 하는 개발: 환불 시 그룹 자동 해제 (서버)
- **조건:** 그룹 공개 강좌(83 B안·103)에서 환불이 잦아질 때만 해요.
- **방식**
  - 우리 서버(예: Vercel 함수)가 아임웹 웹훅 `ORDER_CANCEL_COMPLETE` / `ORDER_REFUND`를 받아요.
  - 주문 상품이 이용권이면 `PUT /member-info/members/{uid}/groups`로 그 그룹만 빼요.
- **보안**
  - 아임웹 개발자센터 앱 등록(OAuth)이 필요해요.
  - 토큰은 서버 환경 변수에만 둬요. 클라이언트 코드에 넣지 않아요.
  - 웹훅 서명 규칙이 문서에 없어요 → 받은 주문 번호로 주문 API를 다시 조회해서 진짜인지 확인해요.
- **주의:** API로 그룹을 바꿀 때 다른 이용권 기간이 사라지지 않는지 시험해야 해요. 그룹 변경이 '갱신' 방식이라서예요. [공식]
- **지금은 하지 않아요.** 관리자 수동 처리로 충분한 규모예요(회원 3명).

### 3-5. 배포 순서 (지금 방식 그대로)
1. 코드는 `SF_SITE.lms.on:false`로 먼저 배포해요. 화면 변화가 없어요.
2. 시험 모드(sf_stage)에서 `on:true`로 바꾼 설정으로 확인해요.
3. Codex 검수를 받아요.
4. 운영 Header Code에 배포해요.
5. 상품 하나(83)씩 켜요.
6. 문제가 생기면 `on:false` → 다시 배포해요. 상품 글의 영상 줄은 전환이 끝날 때까지 지우지 않아요.
