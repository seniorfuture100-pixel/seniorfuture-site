# 런런(Learn Run) LMS 도입 설계 — 시니어퓨처 '나의 강의실' (2026-11-02)

- 목표: LMS를 설치하는 것 자체가 아니에요. 기존 구매·회원 체계를 유지하면서 운영자가 안정적으로 관리할 수 있는 '나의 강의실'을 만드는 거예요.
- 이번 단계에서 한 일: 조사, 설계, 로컬 예시, 검증 준비까지예요.
- 하지 않은 일: 앱 설치, 권한 동의, 유료 구독, 결제, 운영 사이트 게시, 수강권한 변경이에요.
- 함께 만든 파일: 로컬 화면 예시 [`docs/prototype/learnrun-classroom.html`](prototype/learnrun-classroom.html)

**표기**

## 1. 결론

**추천안: "A+ — 지금의 '나의 강의실'을 허브로 두고, 온라인 강의(VOD·다시보기)만 런런 강의실로 보내기"**

- 사이트 안에 메뉴 주소 `learn-run` 페이지를 하나 만들어요. 런런이 공식 지원하는 설치 방식이에요. [공식 S3]
- 지금의 '나의 강의실'(`/shop_mypage/?sf=room`)은 그대로 둬요.
  - 교육 카드의 '강의실 입장'만 런런 강의실로 연결해요.
  - 무료 라이브(Zoom)·커뮤니티 모임(카카오 톡방)·기수 톡방 카드는 지금 방식을 유지해요. 런런 문서에 라이브·출석 기능이 없기 때문이에요. [미확인]
- 이렇게 하면 다음 네 가지를 한 번에 해결해요.
  - 진도율·이어보기·시청 기록·수료증이 생겨요. [공식 S7·S8]
  - 영상 주소를 공개 HTML에 섞어 두던 약점(CX-patch-01)이 없어져요.
  - 수강 권한 판단을 브라우저 대신 런런 서버가 해요.
  - 기존 회원·결제·상품은 아임웹 그대로예요.

**도입 조건** — 아래 6가지가 테스트 강좌로 확인돼야 전환해요.
1. 아임웹에 로그인한 회원이 런런 강의실에서 다시 로그인하지 않고 들어가는지. 카카오·네이버·구글 소셜 로그인 회원 포함이에요. [미확인]
2. 결제 완료일 때만 자동 등록되고, 입금 대기(무통장·가상계좌)에서는 등록되지 않는지. [미확인]
3. 환불·취소 시 권한이 회수되는지. 자동이 아니면 관리자가 회수할 수 있는지. [미확인]
4. 수강 기간(예: 83 VOD 결제일부터 30일)을 설정할 수 있는지. 안 되면 대체 운영안이 필요해요. [미확인]
5. 카카오톡 인앱 브라우저와 휴대폰에서 영상이 재생되는지. [미확인]
6. 오픈 할인 요금과 플랜 표기가 맞는지. [공식 요금표에 계산이 안 맞는 곳이 있어요 — 9절]

**지금 하지 않을 것**
- 네이티브 앱(앱스토어·플레이스토어)
- PWA 설치
- 별도 도메인 분리

이 셋은 런런이 지원하지 않거나 근거가 없어요.

## 3. '앱 형태' 구분과 대안 비교

### 3-1. 앱 형태 4가지

| 방식 | 런런 지원 | 추가 개발 | 비용 | 로그인 | 영상 | 알림 | 유지보수 | 판단 |
|---|---|---|---|---|---|---|---|---|
| ① 아임웹 앱스토어 LMS 앱 | **지원 확인**: 앱 설치 + 메뉴 주소 `learn-run` 또는 위젯 코드 [공식 S1·S3] | 링크 연결 정도 | 런런 월 구독 | 아임웹 회원 연동 [공식/주장 S1], 재로그인 여부 [미확인] | Vimeo 기반 보안 스트리밍 [공식 S10] | 공개 알림 메일 없음 [공식 S12] | 런런 업데이트 의존 | **지금 도입** |
| ② 사이트 안 모바일 웹 강의실(앱처럼) | ①의 강의실 + 우리 '나의 강의실' 허브 | 허브 카드·링크(작음) | 0 | 아임웹 로그인 그대로 | ①과 같음 | 지금처럼 문자·메일 | 우리 코드 | **지금 함께** |
| ③ PWA(홈 화면 추가) | 문서에 언급 없음 [미확인] | 아임웹에서 manifest·서비스워커 넣기 어려움 [해석] | 개발비 | 같음 | 같음 | 웹 푸시 별도 | 높음 | 이후 검토 |
| ④ 네이티브 앱 | 언급 없음 [미확인] | 큼(웹뷰 앱·심사) | 개발·스토어 비용 | 웹뷰 로그인 난이도 높음 | 웹뷰 재생 시험 필요 | 앱 푸시 | 높음 | 지금은 하지 않음 |

"런런 앱 설치"는 아임웹 사이트에 LMS 기능을 붙이는 것이에요. 휴대폰 앱이 생기는 것이 아니에요. [공식 S1·S3]

### 3-2. 연결 방식 A·B·C 비교

| 기준 | A. '나의 강의실' → 런런 기본 강의실 | B. 우리 강의실 홈 → 런런 '강좌별' 학습 화면 | C. 별도 학습 도메인 |
|---|---|---|---|
| 런런 지원 | 지원 확인(메뉴 `learn-run`) | 강좌별 주소(딥링크) **미확인** | 런런은 사이트 안 설치만 안내 → **미지원 근거** |
| 아임웹 회원·결제 | 연동 [공식] | 같음 | 어려움 |
| 로그인 반복 | 미확인(시험 필요) | 미확인 | 반복 가능성 높음 |
| 구매 후 권한 | 상품 연결 자동 등록 [공식 S4] | 같음 | 별도 |
| 모바일 | 런런 화면 의존 | 같음 | — |
| 디자인 유지 | 헤더·푸터는 아임웹, 강의실 안은 테마 색·커스텀 CSS [공식 S5] | 우리 허브 + 런런 | 낮음 |
| 진도·기록 | 런런 | 런런 | — |
| 운영 수작업 | 적음 | 딥링크를 강좌마다 관리 | 많음 |
| 비용 | 런런 구독 | 같음 + 개발 | 높음 |
| 확장·장애 | 런런 장애 시 강의실 전체 영향 | 우리 허브는 살아 있음 | — |

**선정: A+(A를 기본으로, 우리 허브 유지)**
- B는 강좌별 주소를 지원한다는 근거가 없어요. 확인되면 2단계에서 B로 넓혀요.
- C는 근거가 없어요.
- A+는 런런이 지원하는 방식만 쓰면서 라이브·모임처럼 런런이 안 하는 기능을 잃지 않아요.

**제약**
- 런런 강의실 안 디자인은 테마 색·커스텀 CSS 범위에서만 바꿀 수 있어요. [공식 S5, 범위 미확인]
- 강좌별 바로가기가 없으면, 허브에서 누른 뒤 강의실 목록에서 한 번 더 골라야 해요.

## 4. '나의 강의실'을 누른 뒤 흐름 (추천안)

```
[헤더·탭바 '나의 강의실'] → (로그인 안 됨) 로그인 → 돌아올 곳 = 나의 강의실  ← 지금은 주문 목록이라 고쳐야 해요
   ↓
[시니어퓨처 나의 강의실 (허브, 우리 코드)]
   ├ 온라인 강의 (런런)  : 카드 '이어서 듣기' → /learn-run (런런 강의실)
   │                       → 런런 강좌 목록 → 강좌 → 강의 재생·진도·자료·Q&A·수료증
   ├ 기수제 스터디      : 일정·톡방 입장(지금처럼) + '다시보기·자료는 온라인 강의실에서' → /learn-run
   ├ 무료 라이브         : 입장(20분 전부터)·다시보기(지금처럼)
   └ 커뮤니티 모임       : 일시·장소·톡방(지금처럼)
```

- 런런 강의실 안에서 '시니어퓨처 나의 강의실로' 돌아오기: 아임웹 헤더의 '나의 강의실' 링크로 돌아와요. 런런 화면 안에 돌아가기 버튼을 넣을 수 있는지는 미확인이에요.
- 허브에 런런 진도율을 보여 주는 것은 하지 않아요. 런런 데이터를 우리 코드가 읽는 공식 방법(API)이 없어요. [미확인]
- **버튼 숨김과 접근 차단은 달라요.** 허브는 링크만 보여 줘요. 실제 시청 권한은 런런 서버가 판단해요. 허브의 표시·캐시는 권한 근거로 쓰지 않아요.

## 운영 매뉴얼

### 아임웹과 런런 역할 나누기

| 아임웹에서 | 런런에서 |
|---|---|
| 상품(가격·옵션·판매 기간), 결제, 주문·환불 | 강좌·강의·영상·자료·커리큘럼 |
| 회원·회원 그룹 | 상품 연결 또는 그룹 공개 또는 승인형 중 1개, 공개·예약 공개 |
| 메뉴 `learn-run` 페이지 | 진도·시청 기록·Q&A·과제·수료증 |
| 공지·문자·메일 안내 | (공개 알림 메일 없음) |

### 신규 교육 등록
1. 아임웹에 상품을 만들어요(숨김).
2. 런런에 강좌를 만들고 영상을 올려요. 인코딩 완료를 확인해요.
3. 강좌에 상품을 연결해요(또는 그룹 공개).
4. 공개 설정(지금 또는 예약)을 해요.
5. 테스트 계정으로 확인해요(관리자 화면 말고 일반 회원으로).
6. 상품을 판매중으로 바꿔요.
7. 안내 문자·공지를 보내요.

### 구매·수강 관리
- **매일:** 새 결제 ↔ 런런 등록을 대조해요. 누락이 있으면 업체 안내대로 처리해요(수동 등록 기능 미확인).
- **환불 처리할 때 꼭:** ① 아임웹 환불 → ② 런런 수강 해제 → ③ 확인. 자동 회수가 확인되기 전까지 지켜요.
- **무료 초대·연장·기수 이동:** 기능 확인 후 절차를 채워요. 지금은 **미확인**이에요.

### 콘텐츠 관리
- 영상 교체 시 기존 진도에 미치는 영향은 미확인이에요. 교체 전에 테스트 계정으로 확인해요.
- 예약 공개는 최대 1분 늦어요. 공개 안내는 별도로 보내요.

### 고객 문의

| 문의 | 확인 순서 |
|---|---|
| 구매했는데 안 보여요 | 아임웹 주문 상태 → 로그인 계정이 같은지 → 런런 등록 여부 → 누락이면 등록 |
| 다른 계정이에요 | 주문한 계정의 이메일·소셜 로그인 확인 |
| 재생이 안 돼요 | 브라우저(카카오 인앱이면 크롬으로) → 허용 도메인 → 영상 상태 |
| 진도가 안 올라가요 | 계산 기준 확인(미확인) |
| 기간이 끝났어요 | 연장 정책 |
| 수료증 | 수료 조건 충족 여부 |

### 정기 점검

| 주기 | 할 일 | 담당 |
|---|---|---|
| 매일 | 결제 ↔ 등록 대조, 환불 ↔ 해제 대조 | 운영자 |
| 매주 | 업로드 실패 영상, Q&A 답변, 예약 공개 일정 | 운영자·강사 |
| 매월 | 1일 월 시청자 수·용량 80% 알림, 플랜 적정성, 데이터 백업(내보내기 기능 확인 후) | 사장님 |

### 자동화와 사람 확인
- **자동 [공식]:** 상품 결제 → 등록, 그룹 회원 → 등록, 예약 공개, 수료증 발급
- **사람 확인 필수:** 환불·취소 회수, 입금 대기, 기간 연장, 그룹 제외, 기존 구매자 이전, 영상 교체 영향
