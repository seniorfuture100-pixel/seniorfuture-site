# 저장 전 자동 검사 (②단계, 2026-10-22)

공통 코드를 아임웹에 **저장하기 전에** 새 코드로 사이트 전체를 미리 돌려 보고, 지금 사이트와 달라진 곳이 없는지 확인해요.

## 원리 — 시험 모드(`site/blocks/stage.js`, 공통 코드 맨 앞 `sf-stage`)
- 검사하는 탭의 sessionStorage 에 `sf_stage=1` 과 새 코드(`site/dist/stage-code.txt`)를 넣으면,
  그 탭(과 그 안의 iframe)에서만 저장된 공통 코드를 끄고 새 코드를 대신 실행해요.
- 다른 사람·다른 탭·사장님 화면에는 영향 없음. 탭을 닫으면 사라지고, 검사 도구도 끝나면 지워요.

## 검사 내용 (`tools/check/check.js`, 브라우저에서 실행)
화면 23곳 × 모바일 390 · PC 1280:
- 보이는 요소(글자·그림·버튼·sf/r2/r3 부품)의 위치·크기(자기 섹션 안 기준, 움직임 효과 영향 없이)·글자·색·글꼴
- 섹션 위치·크기, 페이지 높이(1% 이상), 빠진/새 요소
- 첫 화면이 그려진 뒤 흔들리는 글자·그림이 새로 생겼는지
- 오류, 가로 넘침, 모바일/PC 헤더, 하단 탭바(보임·스크롤해도 고정), 푸터, 상품 카드 수
동작 검사: 하단 탭 이동·뒤로 가기(본문만 교체), 탭바 고정, 인사이트 페이지 넘김(푸터 유지), 헤더 995/1000px, 상세 이동 대비책

## 순서
1. 원본(`site/blocks`) 고치기 → `node tools/site/assemble.js` (header-code.txt, stage-code.txt 생성)
2. 사이트 탭에서 브리지로 `check.js`·`stage-code.txt` 를 읽어
   `A = __CHK.run({pages, widths:[390,1280]})` (지금 사이트) / `B = __CHK.run({pages, widths, stage: code})` (새 코드)
   `cmp = __CHK.compare(A, B)`, `beh = __CHK.behave({stage: code})`
3. `node tools/check/report.js 결과.json 보고서.md` → **✅ 저장해도 됨** 일 때만 아임웹에 저장
   (일부러 바꾼 곳이 있으면 보고서의 '달라진 화면'이 그 부분뿐인지 사람이 확인)
4. 저장한 뒤 한 번 더: 새로 저장된 사이트 = 시험 모드 결과와 같은지(`__CHK.run` 다시 → compare)
